================================================================================
API остатков товаров — инструкция для партнёра
================================================================================

Назначение: получение остатков товаров интернет-магазина (только чтение).
Методы записи (POST, PUT, PATCH, DELETE) не поддерживаются.

В выдачу входят только товары со складским остатком строго больше порога
(по умолчанию более 50). Реальное количество не передаётся: в поле
stock_quantity приходит текст вида «более 50».


--------------------------------------------------------------------------------
1. Endpoint
--------------------------------------------------------------------------------

  GET https://medknigaservis.ru/wp-json/mks-core/v1/stock

  Метод        — GET (получить данные)
  Базовый URL  — https://medknigaservis.ru
  Префикс REST — /wp-json/
  Путь API     — mks-core/v1/stock

Точный URL при необходимости уточняется у магазина (может быть изменён
в настройках).


--------------------------------------------------------------------------------
2. Авторизация
--------------------------------------------------------------------------------

Используются ключи WooCommerce REST API с правами Read.
Ключи выдаёт сторона магазина.

Передача ключей — ТОЛЬКО через HTTP Basic Authentication в заголовке
Authorization:

  Username (логин)  — consumer_key
  Password (пароль) — consumer_secret

Заголовок формируется так:

  Authorization: Basic BASE64(consumer_key:consumer_secret)

где BASE64 — кодирование строки «ключ:секрет» в Base64.

Ключи в query-параметрах URL не передавайте.

HTTPS обязателен: WooCommerce принимает Basic Auth только по SSL.

Без корректных ключей ответ будет 401 или 403.


--------------------------------------------------------------------------------
3. Параметры запроса (query)
--------------------------------------------------------------------------------

  Параметр     Обязательный   По умолчанию          Описание
  ----------   ------------   -------------------   ----------------------------
  page         нет            1                     Номер страницы (≥ 1)
  per_page     нет            из настроек магазина  Товаров на странице (1…100)

Для полной выгрузки рекомендуется:

  per_page=100
  page от 1 до значения заголовка X-WP-TotalPages


--------------------------------------------------------------------------------
4. Заголовки ответа (пагинация)
--------------------------------------------------------------------------------

  X-WP-Total       — всего товаров в выборке
  X-WP-TotalPages  — всего страниц при текущем per_page

Число страниц зависит от количества товаров с остатком выше порога.


--------------------------------------------------------------------------------
5. Поля одного товара в ответе
--------------------------------------------------------------------------------

Тело ответа — JSON-массив объектов.

  Поле                  Тип             Описание
  --------------------  --------------  ----------------------------------------
  name                  string          Наименование
  sku                   string          Артикул
  isbn                  string          Значение атрибута ISBN (пусто, если
                                        не задано)
  stock_quantity        string          Текстовый остаток: «более N»
                                        (N — порог на стороне магазина,
                                        по умолчанию «более 50»).
                                        Точное число не отдаётся.

В выдачу попадают только:

  — тип simple, статус publish;
  — нужный атрибут-фильтр (настраивается магазином);
  — остаток в БД строго больше порога (по умолчанию 50).


--------------------------------------------------------------------------------
6. Пример запроса
--------------------------------------------------------------------------------

  curl -u "ck_xxxxxxxx:cs_yyyyyyyy" \
    "https://medknigaservis.ru/wp-json/mks-core/v1/stock?page=1&per_page=100"

Эквивалент с явным заголовком Authorization:

  curl -H "Authorization: Basic $(printf '%s' 'ck_xxxxxxxx:cs_yyyyyyyy' | base64 -w0)" \
    "https://medknigaservis.ru/wp-json/mks-core/v1/stock?page=1&per_page=100"

Пример ответа:

  [
    {
      "name": "Пример книги",
      "sku": "12345",
      "isbn": "978-5-9704-8204-9",
      "stock_quantity": "более 50"
    }
  ]

Пример заголовков:

  X-WP-Total: 1200
  X-WP-TotalPages: 12


--------------------------------------------------------------------------------
7. Как забирать все остатки (логика сессии)
--------------------------------------------------------------------------------

  1. Запросить page=1&per_page=100 (с Basic Auth в заголовке Authorization).
  2. Прочитать заголовок X-WP-TotalPages.
  3. Последовательно запросить page=2 … page=N (тот же per_page=100).
  4. Следующий запрос — только после ответа предыдущего
     (запросы строго по одному, без параллели).
  5. Между запросами — пауза 500 мс.
  6. Длительность одной полной сессии зависит от числа страниц;
     ориентир при ~50 страницах ≈ 1,5–2,5 минуты.
  7. Новую сессию не запускать, пока не завершилась предыдущая.

При ошибке сети или ответе 5xx:
  — 2–3 повтора той же страницы с паузой 2–5 с;
  — при неудаче остановить сессию и зафиксировать ошибку.


--------------------------------------------------------------------------------
8. Периодичность сессий
--------------------------------------------------------------------------------

  Режим                Интервал           Комментарий
  -------------------  -----------------  --------------------------------------
  Стартовый            раз в 60 минут     Рекомендуемый режим по умолчанию
  Ускоренный           раз в 30 минут     Если нужно быстрее учитывать продажи
                                          на сайте
  Чаще 30 минут        не рекомендуется   Почти не даёт свежести данных,
                                          только лишняя нагрузка на магазин
